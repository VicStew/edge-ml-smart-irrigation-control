# Sensor ESP32 Firmware

This folder contains the firmware and helper script for a sensor ESP32. The current sketch replays recent weather samples from a generated header file and sends them to a section ESP32 over ESP-NOW.

## Execution Order

1. Generate or refresh the sample weather header:

   ```sh
   python3 fetch_recent_weather.py
   ```

   By default this fetches recent Open-Meteo data for the configured latitude, longitude, and timezone, then writes `recent_weather_sample.h`.

2. Flash the section ESP32 from `../section_esp` or at least confirm the section node MAC address.

3. Edit `sensor_esp.ino`:

   - Set `NODE_ID` for this sensor.
   - Set `SECTION_ID` to the target farm section.
   - Set `section_mac` to the WiFi station MAC address of the section ESP32.
   - Confirm `WIFI_CHANNEL` matches the master and section nodes.

4. Open `sensor_esp.ino` in the Arduino IDE, PlatformIO, or another ESP32 Arduino build environment.

5. Flash the sketch to the sensor ESP32.

6. Power the section node, master node, and sensor node. The sensor will start sending weather packets and heartbeat packets.

## Runtime Flow

1. `setup()` starts serial output, sets WiFi station mode, and registers the section node as an ESP-NOW peer.
2. `loop()` sends a weather packet every `SEND_INTERVAL_MS`.
3. `read_weather_sample()` reads the next row from `RECENT_WEATHER_SAMPLES` and cycles through the 24 stored samples.
4. `send_weather_packet()` sends temperature, humidity, soil temperature, evapotranspiration, and shortwave radiation to the section node.
5. `send_heartbeat()` sends periodic status packets containing uptime and sent-packet count.
6. Control commands and acknowledgements received from the section node are printed over serial.

## Files

- `sensor_esp.ino` - Main firmware for the sensor node. Defines the ESP-NOW packet format, sends weather data, sends heartbeat status, and logs incoming control or acknowledgement packets.
- `fetch_recent_weather.py` - Fetches the latest 24 past hourly weather samples from Open-Meteo and writes both a CSV and Arduino header.
- `recent_weather_sample.h` - Generated Arduino header containing the 24 weather samples used by `sensor_esp.ino`.

## Helper Script Options

```sh
python3 fetch_recent_weather.py \
  --latitude -0.4201 \
  --longitude 36.9476 \
  --timezone Africa/Nairobi \
  --csv-output recent_weather_24h.csv \
  --header-output recent_weather_sample.h
```

`recent_weather_24h.csv` is generated by the script but is not required by the firmware. The firmware only includes `recent_weather_sample.h`.

## Configuration Notes

- Keep `WIFI_CHANNEL` identical across all ESP32 sketches.
- The current firmware uses generated sample data. Replace `read_weather_sample()` if physical sensors are connected.
- The packet structure must stay compatible with `section_esp.ino` and `master_esp.ino`.
